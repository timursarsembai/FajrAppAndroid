# FajrApp Android — Security Checklist

Дата: 2026-05-30  
Версия приложения: 1.0.0  
Проверяющий: _TBD_

## 1. Подготовка
- [ ] Зафиксировать commit hash проверяемой сборки.
- [ ] Проверить, что аудит проводится на `release`-конфигурации (не `debug`).
- [ ] Проверить `targetSdk`, `minSdk`, `compileSdk`.
- [ ] Убедиться, что включены базовые проверки CI (lint, unit, androidTest).

## 2. Манифест и компоненты
- [ ] Проверить `AndroidManifest.xml` на лишние разрешения.
- [ ] Проверить `android:exported` у `Activity/Service/Receiver/Provider`.
- [ ] Убедиться, что нет случайно экспортированных внутренних экранов.
- [ ] Проверить `intent-filter` на нежелательные deep-link точки входа.
- [ ] Проверить `taskAffinity`, `allowBackup`, `debuggable` в release.

## 3. Разрешения (Permissions)
- [ ] Проверить минимально необходимые runtime-permissions.
- [ ] Убедиться, что локация запрашивается только при необходимости.
- [ ] Проверить graceful fallback при отказе в разрешениях.
- [ ] Проверить, что нет фоновых разрешений без явной необходимости.

## 4. Сетевой слой
- [ ] Проверить использование HTTPS везде, где есть сеть.
- [ ] Проверить `networkSecurityConfig` (запрет cleartext, pinning при необходимости).
- [ ] Проверить обработку TLS ошибок (не должно быть bypass).
- [ ] Проверить таймауты, retry-политику, обработку offline.

## 5. Хранение данных
- [ ] Проверить, какие данные лежат в `SharedPreferences`.
- [ ] Убедиться, что чувствительные данные не хранятся в открытом виде.
- [ ] Для чувствительных данных: использовать EncryptedSharedPreferences/Keystore.
- [ ] Проверить отсутствие секретов, токенов и ключей в ресурсах/коде.
- [ ] Проверить поведение при backup/restore.

## 6. Логирование и приватность
- [ ] Проверить, что PII (локация, user data) не утекает в логи.
- [ ] Убедиться, что debug-логи выключены в release.
- [ ] Проверить обработку исключений без вывода чувствительных данных.

## 7. WebView / внешние данные (если применимо)
- [ ] Проверить, что `javascriptEnabled` выключен, если не нужен.
- [ ] Проверить, что `addJavascriptInterface` не используется небезопасно.
- [ ] Проверить блокировку file/content доступа в WebView.
- [ ] Проверить валидацию внешних URL перед открытием.

## 8. Криптография
- [ ] Проверить, что нет самописной криптографии.
- [ ] Проверить алгоритмы/режимы (без ECB, без слабых hash/PRNG).
- [ ] Проверить использование Android Keystore для ключей.

## 9. Сборка и поставка
- [ ] Проверить `minifyEnabled`/R8 для release.
- [ ] Проверить наличие и корректность `proguard-rules.pro`.
- [ ] Проверить подпись release-артефактов.
- [ ] Проверить, что debug-only инструменты не попадают в release.

## 10. Зависимости и supply chain
- [ ] Провести аудит зависимостей (известные CVE, устаревшие версии).
- [ ] Проверить прямые и транзитивные зависимости Gradle.
- [ ] Проверить источники артефактов (MavenCentral/Google и т.д.).
- [ ] Зафиксировать критичные версии библиотек.

## 11. Локализация и обработка пользовательского ввода
- [ ] Проверить безопасную обработку вводимых пользователем строк.
- [ ] Проверить отсутствие падений/corruption на нестандартных символах.
- [ ] Проверить, что транслитерация/локализация не ломает логику и не вызывает утечек данных.

## 12. Уведомления и будильники
- [ ] Проверить, что PendingIntent создается с корректными флагами (`IMMUTABLE`/`MUTABLE`).
- [ ] Проверить, что BroadcastReceiver/Service для будильников не экспортированы лишне.
- [ ] Проверить отсутствие возможности внешнего триггера внутренних интентов.

## 13. Тестирование безопасности
- [ ] Статический анализ: Android Lint + custom checks.
- [ ] Динамический анализ на реальном устройстве.
- [ ] Проверка на tampering/root (если требуется моделью угроз).
- [ ] Негативные тесты: отказ разрешений, плохая сеть, битые данные.

## 14. Итоговый отчет
- [ ] Список найденных уязвимостей с severity (Critical/High/Medium/Low).
- [ ] Шаги воспроизведения для каждой проблемы.
- [ ] Рекомендации по исправлению.
- [ ] Повторная верификация после фиксов.
